## Architecture Decisions Made

1. **tarx-martech is standalone** — lives at ~/Desktop/tarx-martech/, NOT inside tarx-code-oss/extensions/. Rationale: martech is business ops, not IDE functionality. Independent deployment lifecycle. Still uses shared SQLite via @tarx/shared-db file: reference.

2. **Claude Desktop IS the content engine** — No @anthropic-ai/sdk dependency. Claude Desktop calls martech_store_email after generating content in conversation. The LLM is the caller, not the callee.

3. **esbuild for MCP servers** — Same pattern as tarx-ops: single bundled ESM output. No tsc (avoids "Type instantiation excessively deep" with MCP SDK + Zod).

4. **martech_ table prefix** — All 5 tables use martech_ prefix in the shared memory.db to avoid collisions with existing 40+ tables.

5. **Invite code reuse** — tarx-martech reads unused codes from tarx-core's invite_codes table directly. No duplication of code generation logic.

6. **No GoDaddy API in MCP** — DNS mutations only via setup-email-infra.mjs script. MCP tools are read-only for DNS (check propagation only).
